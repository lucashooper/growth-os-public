### 3. ✅ Analytics Page Still Loading After Navigation

**Issue**: Prefetching wasn't working - data still loads after clicking Analytics.

**Root Cause**: 
1. `api-client.ts` cache needs proper implementation
2. Prefetch only queues the request, doesn't guarantee cache hit
3. No stale-while-revalidate pattern

**Solution Implemented**: Hover prefetching in sidebar (300ms delay)

**How It Works Now**:
1. User hovers over "Analytics" link
2. After 300ms, prefetch fires: `apiFetch(/api/insights/${projectId})`
3. Response cached in `api-client.ts` with 2-minute TTL
4. When user clicks, data loads instantly from cache

**Caveats**: 
- First visit after page load won't be instant (no cache yet)
- Need to verify `api-client.ts` properly caches responses
- May need to implement proper cache layer with `getCached/setCached`

**Next Steps**: 
- Add cache hit/miss logging to verify prefetching works
- Implement longer TTL for Analytics data (5 minutes)
- Add background refresh on active tab

## Image Loading Investigation Next Steps

Based on the detailed error logs we'll now get, we need to:

1. **Identify URL Patterns**
   - Which domains are failing? (TikTok CDN, Supabase, etc.)
   - Are all images from same source failing?
   - Or mixed?

2. **Check CORS Headers**
   - TikTok CDN may be blocking cross-origin requests
   - Supabase images should work (same domain)

3. **Check URL Expiration**
   - TikTok CDN URLs often have `?x-expires=` parameter
   - These expire after hours/days
   - Need to re-fetch or proxy

4. **Implement Image Proxy**
   ```
   /api/image-proxy?url=https://tiktocdcdn.com/...
     ↓
   Check cache in DB
     ↓
   If expired: Re-download, save to Supabase
     ↓
   Return cached URL
   ```
